# Эксплуатация мигратора

Все примеры выполняются из корня репозитория.

## 1. План (read-only для Google Drive и Seafile)

```bash
python3 scripts/drive_to_seafile_all_v6.py --plan
```

В `~/rclone-migration-duplicates/manifest.json` будут записаны ID, пути и размеры. При повторном вызове `--plan` использует существующий манифест (не обновляет его). Для нового содержимого исходной папки нужен **новый рабочий каталог**, а для возобновления переноса — строго тот же манифест.

Ожидаемые исторические ориентиры: 115 папок, 6604 файла, 59 переименованных коллизий, `unsupported=0`. Числа могут измениться, если изменилось содержимое источника.

## 2. Перенос

```bash
python3 scripts/drive_to_seafile_all_v6.py \
  --run --workers 4 --request-delay 0.5 --retries 7 --retry-wait 10
```

Рекомендуется начинать с четырех воркеров на машине с 2 GiB RAM, а не с 15. V6 запускает локальный `rclone rcd` на динамическом порту `127.0.0.1` и использует `backend copyid`, чтобы различать файлы с одинаковыми именами. Во время копирования печатаются строки `COPIED` после завершения передачи. Работа с Google Drive — чтение; удаление/перезапись объектов в источнике не предусмотрены.

**Важно о destination:** не запускайте новый перенос поверх неизвестного содержимого в `GoogleDrive-Import`; скрипт намеренно отказывается перезаписывать нерегистрированные объекты. Рабочие файлы `state_v5.json` и `manifest.json` относятся к конкретному переносу.

## 3. Мониторинг (опционально)

Узнать порт RC:

```bash
ps -ef | grep '[r]clone rcd'
```

Затем подставить его в монитор:

```bash
python3 scripts/rclone_monitor.py --port 56679
```

Порт в примере условный; он меняется при каждом запуске. Монитор выводит `UPLOADING`, `PROGRESS` и `COPIED` по информации RC. `COPIED` в мониторе означает завершение, зарегистрированное Rclone, а не завершенную контрольную проверку. Монитор необязателен: `Ctrl+C` в нем не останавливает перенос.

Для проверки общей статистики:

```bash
curl -sS -X POST http://127.0.0.1:56679/core/stats | python3 -m json.tool
```

## 4. Возобновление

После прерывания используйте прежний workdir и тот же набор параметров:

```bash
python3 scripts/drive_to_seafile_all_v6.py --run --workers 4 --request-delay 0.5 --retries 7 --retry-wait 10
```

**Не удаляйте `state_v5.json`**. Если операция фактически закончилась, но статус не успел сохраниться, файл может оказаться на сервере, но отсутствовать в состоянии. В этом случае скрипт останавливается без перезаписи; сначала вручную сверяйте данные, затем исправляйте состояние осознанно.

## 5. Проверка

```bash
python3 scripts/drive_to_seafile_all_v6.py --verify
rclone lsf seafile:GoogleDrive-Import --recursive --files-only | wc -l
rclone size seafile:GoogleDrive-Import
```

Пример достигнутого результата:

```text
Finished: copied=0, verified=6604, errors=0, unsupported=0
SUCCESS: all expected paths and reported sizes matched.
```

`--verify` проверяет **наличие папок, имена/пути и размеры файлов**, но **не MD5/SHA, хеши всего содержимого или возможность декодировать видео**. Для файлов Google Docs без размера исходника проверяется только наличие. Если нужна более сильная верификация, отдельно сравните контрольные суммы или прочитайте содержимое выбранных файлов.

## 6. Что сохранить, а что публиковать

Архивируйте отдельно и приватно `~/rclone-migration-duplicates/{manifest.json,state_v5.json,errors_v6.json}`. Эти файлы могут раскрывать структуру/имена пользовательских данных и **не должны попадать в публичный Git**.

Не публикуйте настоящий `rclone.conf`, OAuth-токены, пароли, логи с приватными путями. Конфигурация Rclone в архиве — только пример.
